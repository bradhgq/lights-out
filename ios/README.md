# Lights Out for iOS

Personal-use iOS companion to the macOS app. Same idea: restrict selected apps and
web domains at bedtime, with heavy typing friction to override.

This target is **not** ready for App Store distribution — it uses Apple's Screen Time
(Family Controls) API, which requires a separately-granted distribution entitlement.
For now the assumption is sideload-to-personal-device-via-Xcode.

## Prerequisites

- macOS with Xcode 16+ (matching the iOS 17 deployment target)
- **A paid Apple Developer Program membership ($99/yr).** A free "Personal Team" is
  *not* sufficient — see [Account requirements](#account-requirements) below.
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`)
- A physical iPhone — Screen Time APIs do **not** function in the simulator

## Account requirements

Running this on a device requires a **paid** membership. Two separate capabilities
block the free tier, and both are load-bearing here:

- **App Groups** — how the main app hands config and phase state to the three
  extensions. A free Personal Team cannot use App Groups at all (same for push,
  iCloud, and associated domains); the build fails at sign time with the
  provisioning profile missing the capability.
- **Family Controls** — the capability is only offered to paid teams. Note that
  *development* profiles can authorize it without Apple's written approval; the
  formal request is only needed for **distribution**.

There is no code-level workaround: extensions have separate containers, so without
App Groups the monitor extension cannot read the config at all.

What *does* work on a free account: **simulator builds**, which is enough to verify
the code compiles and to iterate on UI. Screen Time APIs silently no-op there, so no
shielding behavior can be tested.

```bash
xcodebuild -project ios/LightsOutiOS.xcodeproj -scheme LightsOutiOS \
  -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17' \
  CODE_SIGNING_ALLOWED=NO build
```

## Build & install

```bash
cd ios
xcodegen generate
open LightsOutiOS.xcodeproj
```

In Xcode:

1. Select the `LightsOutiOS` target → Signing & Capabilities → set your Team.
2. Repeat for each extension target: `LightsOutMonitor`, `LightsOutShield`,
   `LightsOutShieldAction`.
3. Ensure each target's **bundle identifier is unique** (they already differ by suffix;
   if Xcode complains about duplicates, change the prefix in `project.yml`).
4. Ensure each target has the `com.apple.developer.family-controls` entitlement — this
   is generated by XcodeGen but needs Apple to recognize it against your provisioning
   profile. If you hit a signing error, see **Family Controls entitlement** below.
5. Plug in an iPhone, select it as the run destination, build & run.

## First launch

The onboarding wizard will:

1. Ask for Screen Time authorization (system alert — tap **Continue**, then **Allow**).
2. Let you pick the apps, categories, and web domains to restrict (`FamilyActivityPicker`).
3. Let you set the four phase times (amber, wind-down, lights-out, morning reset).
4. **Walk through setting up grayscale Shortcuts** (optional, skippable — see next
   section).
5. Write the config and register the DeviceActivity schedules.

You're done. The next phase boundary will fire automatically.

## Grayscale via Shortcuts

iOS has no public API to toggle Color Filters / Grayscale. The grayscale setup wizard
walks you through two options:

**Option A (recommended): Personal Automations.** In Shortcuts → Automation → Personal
Automation → Time of Day → 22:30 (your amber time) → Add action → "Set Color Filters"
→ On. Save with "Run without asking". Create a second automation at your morning-reset
time to turn it back off. This runs entirely on-device without Lights Out being open.

**Option B: Named Shortcuts.** Create two regular Shortcuts named exactly
`Lights Out — Grayscale On` and `Lights Out — Grayscale Off` (or custom names you
set in the wizard). When the main app is foregrounded — e.g. via "Enter Lights Out
now" — it calls `shortcuts://run-shortcut?name=…` to trigger them.

The wizard offers test buttons that try to run each named shortcut immediately,
so you can verify everything is wired up before bedtime.

## Family Controls entitlement

Personal use on your own device: the entitlement in the `*.entitlements` files is
enough to build and sign **with a paid team** — you don't need to file anything with
Apple for development. It will not work on a free Personal Team; see
[Account requirements](#account-requirements).

If you ever want to distribute: Apple requires you to submit a written request to
receive the production Family Controls entitlement. Lead time is weeks. Not a concern
for this personal build.

## Troubleshooting

**XcodeGen silently generates a broken project.** If `xcodegen generate` prints
`No "base" settings found` (and the same for `debug config` / `iOS`), it failed to
locate its `SettingPresets` bundle. The generated project then has no
`PRODUCT_NAME = $(TARGET_NAME)`, every target builds to a nameless product, and
`xcodebuild` fails with `Multiple commands produce '.../.app'` — which looks like a
project-spec bug but isn't.

This happens when XcodeGen is installed via Nix and invoked through the profile
symlink: it resolves `SettingPresets` relative to the invoked path, and the Nix
profile links `bin/` but not `share/xcodegen/`. Invoke the store binary directly:

```bash
$(readlink -f $(which xcodegen)) generate
```

### Shared with the macOS app

Pure-Swift types (`Phase`, `Timeline`, `FrictionText`, `LightsOutConfig`) live in
`../Sources/LightsOutCore` and are consumed by both platforms. The iOS Xcode project
references the repo-root Swift package via `project.yml` → `packages.LightsOutCore`.

### Phase model

Three `DeviceActivitySchedule`s run concurrently, one per restrictive phase. Each has
its own named `ManagedSettingsStore`:

| Phase       | Store name        | Default restrictions               |
|-------------|-------------------|------------------------------------|
| `amber`     | `phase.amber`     | Web domains only (soft nudge)      |
| `windDown`  | `phase.windDown`  | Web domains + app categories       |
| `lightsOut` | `phase.lightsOut` | Everything the user picked         |

Shields union across stores, so phases layer naturally. At morning reset all three
`intervalDidEnd` callbacks fire and each clears its own store.

## Known limitations

- **Grayscale** is user-automation-driven; see above.
- **App Store** distribution needs Apple's production Family Controls entitlement
  (not yet requested).
- **Simulator** can't exercise Screen Time APIs — everything silently no-ops.
- **Shield action extension** can't reliably open URLs, so the override flow uses an
  App Group UserDefaults key that the main app reads on foreground rather than a URL
  handoff. This means the override sheet appears the next time you launch the app
  after tapping "Request override" on a shield (i.e. the user must manually reopen
  Lights Out to complete the override — which is an acceptable extra friction step).
- **Per-app overrides** are not granular: granting an override lifts the shield for
  an entire phase, not a single app. A future enhancement could subtract the specific
  ApplicationToken from the shield set and re-add after the timer.

## Testing

Pure-Swift logic (phase math, friction text, config validation) is tested via the
top-level Swift package:

```bash
cd ..
swift test
```

iOS-specific code has no automated tests — Screen Time APIs can't be unit-tested
without a real device and user authorization. Manual test checklist:

- [ ] Onboarding: fresh install → authorization → picker → times → grayscale →
      dashboard appears.
- [ ] Dashboard countdown ticks live and matches phase boundaries.
- [ ] At amber time, opening a blocked web domain shows the amber-colored shield.
- [ ] At lights-out time, opening a blocked app shows the indigo shield.
- [ ] "Request override" shield button → reopen app → friction sheet appears with
      phrase entry + timer.
- [ ] Typing the phrase correctly + picking a duration clears the shield for that
      duration.
- [ ] Morning reset: shields clear, phase dashboard shows "Daytime".
- [ ] Reboot during windDown: shields remain active after reboot (DeviceActivity is
      persistent).
- [ ] "Enter Lights Out now" from dashboard → confirmation → shields applied + grayscale
      Shortcut runs (if configured).
